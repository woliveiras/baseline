# Project documentation

Document shipped API, architecture, setup, configuration, operations, and onboarding behavior. Read the active spec and code first. Update existing pages rather than duplicating them; create a new page only when no current surface owns the topic. Test example commands where practical and identify any example that remains illustrative.

For architecture, follow the repository's notation first. Otherwise copy the bundled [C4-based project architecture asset](../assets/project-c4-template.md). Start with system context and containers; add component, dynamic, or deployment views only when they answer a real audience question. Every element needs a name, type, responsibility, and relationship. Diagrams never replace prose about ownership, invariants, failure behavior, or accepted decisions.

The C4 model source and current diagram guidance are at https://c4model.com/diagrams.
